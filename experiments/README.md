# experiments — 实验体系实现层

这里是 Hydroweave 实验体系的代码落点：每个实验一个子目录，把体系里的
**数学原理 → 经验公式 → EDA 规律 → 误差分析** 四环落到可运行、可验收的代码。

实验层只读消费 catalog 登记的数据卷，**不写原始数据**；产物统一落到
`data/analysis/<experiment>/runs/<run_id>/`。

## 每个实验必须交代的五件事

一个实验够格进这个目录，需要同时给出下列五项，缺一项就不算完成：

| 要素 | 要求 | 反例 |
|---|---|---|
| 数学定义 | 物理量的连续定义 + 离散化方式 + 常数取值 | 只写"计算 PW"而不说积分方式 |
| 经验公式 | 每条经验公式的适用条件与已知偏差 | 用 Magnus 水上式却不说高空 RH 偏低 |
| 数据口径 | 单位、层序、地形、分母的判定规则 | 不剔除地形以下填充层 |
| 误差边界 | 数值 / 口径 / 代理三类误差分别量化 | 只报一个笼统的"误差 5%" |
| 验收路径 | 独立重算或对抗性检查，标准先定后跑 | 用实验代码本身验证实验代码 |

## 通用约定

- 配置只有一个入口（`config.yaml`）：卷 ID / 数据集 ID / 区域 / 年份 / 阈值全部可改，代码里不出现机器专属路径；
- 每次运行写 `manifest.json`：配置哈希、输入逻辑指纹、Git revision、关键包版本、完成年份、失败日期、产物 SHA-256；
- 年度/批处理产物先写 `.part` 再原子替换，支持中断后按 `--run-id` 续跑；
- 同 `--run-id` 的配置或输入指纹变化会直接报错，防止两套口径的产物混放。

## 运行

`experiments` 是项目根下的包，需要项目根与 `src` 同时在 `PYTHONPATH`：

```bash
PYTHONPATH=src:. .venv/bin/python -m experiments.<name>.<entry> --help
```

`tests/test_tp_cloud_water_experiment.py` 使用
`scripts/demo/make_tp_cloud_water_fixture.py` 生成的合成卷做端到端验证，
不需要外接盘。合成数据只验证链路与可复现机制，**其数字无物理意义**。
